# MAGI 사용자 가이드

MAGI는 개발 요청을 인터뷰와 검토를 거쳐 구현 명세로 정리합니다. 이 문서는 작업 공간에서 요청을 작성하고, 질문에 답하며, 명세를 수정·승인하고 저장된 지식을 활용하는 방법을 설명합니다.

소스 설치는 [README](../README.md#설치와-빠른-시작), Google 로그인·DB·배포 설정은 [공개 서비스 운영](PUBLIC_SERVICE.ko.md)을 참고하세요.

## 작업 시작

공개 서비스에서는 Google 로그인 후 작업 공간을 사용할 수 있습니다. 본인에게 허용된 작업만 조회할 수 있으며, 관리자 기능은 별도 권한이 필요합니다. 인증 없는 개인용 로컬 모드도 지원합니다.

새 세션에서 구현하려는 제품이나 기능을 입력합니다. 다음 내용이 있으면 함께 작성할 수 있습니다.

- 만들려는 기능과 사용 대상
- 사용 환경·플랫폼과 기존 프로젝트의 조건
- 반드시 필요한 동작과 제외할 범위
- 데이터·외부 연동·비용·운영상의 제한

이미 알고 있는 조건을 적으면 인터뷰가 해당 내용을 반영하고, 구현 방향을 결정하는데 부족한 사항을 질문합니다. 작성한 요청은 사용자 원문으로 보존됩니다.

## 질문에 답하기

질문은 단일 선택, 복수 선택 또는 직접 입력으로 표시됩니다. 선택형 질문에도 직접 입력 항목이 있으며, 복수 선택에서는 선택한 항목과 직접 입력 내용을 함께 제출할 수 있습니다.

답한 질문만 제출할 수 있습니다. 직접 입력을 선택했다면 내용을 작성해야 합니다. 제출한 답변은 작업 기록에 저장되며 이후 요구사항과 명세의 근거로 사용됩니다. 질문이나 선택지가 변경된 경우에는 현재 표시되는 폼으로 답변해야 합니다.

사용자가 확정하지 않은 사항은 명시된 가정과 구분합니다. 명세 검토에서 제안한 수치나 동작을 사용자 결정으로 취급하지 않습니다.

## 명세 생성과 검토

MAGI는 현재 근거와 미해결 사항을 보고 다음 작업을 계획합니다. 작업 하나가 끝나면 결과를 반영해 계획을 갱신합니다.

```text
계획 → 자료 확인·인터뷰·요구사항 정리·명세 작성·검토 중 필요한 작업 → 재계획
              질문·수정 대기 또는 검토된 후보의 승인 대기
```

요구사항에 비해 누락되거나 모순된 명세는 보완합니다. 범위·사용자 동작·데이터·비용에 영향을 주는 결정이 부족하면 추가 질문을 표시합니다. 단순한 명세 결함을 해결하기 위해 이미 확정한 요구사항을 임의로 바꾸지 않습니다.

명세에는 요구사항, 설계, 데이터 흐름, 오류 처리, 인수 조건과 테스트 계획이 포함됩니다. 사용자 요청과 답변, 수정 의견, 모델의 가정을 구분하며 관련 근거를 명세 항목과 연결합니다.

| 상태 | 의미와 사용 방법 |
|---|---|
| `NEEDS_USER_INPUT` | 질문에 답하거나 필요한 결정을 입력합니다. |
| `PASS_PENDING_USER_APPROVAL` | 검토를 통과한 문서를 읽고 승인하거나 수정 의견을 보냅니다. |
| `CRITICAL_BLOCKED` | 추가 결정이나 실행이 필요합니다. 대기 이유를 확인하고 수정 의견 또는 추가 실행을 선택합니다. |
| `FINALIZED` | 사용자가 승인한 최종 명세입니다. 다운로드하거나 후속 요청을 이어갈 수 있습니다. |

## 수정과 승인

승인 후보의 동작·범위·조건이 의도와 다르면 수정 의견을 제출합니다. 기존 요청과 답변은 유지하며 새 의견을 반영해 명세를 다시 정리하고 검토합니다.

질문 대기 중에도 공통 입력창으로 수정 의견을 보낼 수 있습니다. 실행 중 작성한 의견은 초안으로 보존되며 대기 상태가 되면 제출할 수 있습니다. 자유 입력은 최종 승인으로 처리하지 않습니다.

검토 통과는 사용자 승인을 대신하지 않습니다. 승인 대기 상태에서 사용자가 승인하면 `final/FINAL_AGENT_SPEC.md`가 생성됩니다.

완료된 세션에서도 후속 요청을 이어갈 수 있습니다. 이전 완료본은 보존되므로 과거 문서와 새 처리 결과를 구분해 볼 수 있습니다.

## 대화와 실행 이력

작업 공간에는 요청·질문·답변·수정 의견과 처리 결과가 표시됩니다. 실행 이력에서는 요청 분석, 요구사항 확정, 명세 생성, 검토와 승인 단계를 선택할 수 있습니다.

현재 계획을 펼치면 목표, 다음 행동의 이유, 수행한 작업과 문서 버전을 확인할 수 있습니다. 자동 실행 한도에 도달하면 완료된 결과를 유지한 채 기다립니다. 내용을 보완하거나 **저장된 결과로 추가 실행**을 선택하면 새 실행 구간을 시작합니다. 추가 실행에도 사용량·비용 제한이 적용됩니다.

서버가 재시작되면 저장된 결과를 복원하고 명시적인 재개를 기다립니다. 이전 호출의 완료 여부가 불명확하면 자동으로 재전송하지 않으며 화면에 확인이 필요한 이유를 표시합니다.

선택한 단계의 결과, 검토 항목과 문서를 확인할 수 있으며, 다운로드도 선택한 문서 버전을 기준으로 합니다. 검토 이슈는 신규·계속·해소 상태를 구분합니다.

## 명세 언어와 다운로드

명세의 기준 원문은 영어이며, 화면에서는 **한국어 / English**를 선택할 수 있습니다. 기본 표시는 한국어입니다.

- 문서 보기와 Markdown 보기는 선택한 언어를 사용합니다.
- Markdown 다운로드는 현재 선택한 언어본을 UTF-8 파일로 제공합니다.
- 한국어본 파일명에는 `.ko.md`가 붙습니다.
- 한국어본은 선택한 영어 문서를 기준으로 생성하며, 같은 원문의 저장된 번역본을 재사용합니다.
- 번역에는 추가 모델 호출 비용이 발생할 수 있습니다.

한국어본을 생성하는 동안에는 해당 언어의 다운로드가 준비될 때까지 기다려야 합니다. 번역에 실패하면 다시 시도하거나 English에서 원문을 열 수 있습니다. 번역은 영어 원문과 검토·승인 상태를 바꾸지 않습니다.

## 지식 검색과 그래프

### 프로젝트 공통 결정

새 요청에서 개인 프로젝트를 선택하거나 만들면 여러 대화를 같은 프로젝트에 둘 수 있습니다. 프로젝트를 선택하지 않으면 별도 프로젝트로 시작합니다. 기존 대화의 이동과 다른 사용자와의 공유는 지원하지 않습니다.

승인 명세의 **승인본의 공통 결정 등록**에서 원문·적용 조건·작성 주체·출처를 확인해 등록합니다. 명세와 출처가 연결된 구조화 결정만 등록할 수 있으며, 과거 문서의 문장을 자동으로 추출하지 않습니다.

다음 요청에서는 재사용할 결정을 직접 선택하세요. 등록한 결정도 기본 선택하지 않습니다. 선택한 결정과 적용 조건은 요청 접수 당시의 사본으로 보존되며, 등록 해제나 새로운 승인본이 과거 작업을 바꾸지 않습니다. 등록 이후 새 승인본이 있으면 안내하고, 출처가 삭제되거나 검증되지 않으면 신규 재사용을 차단합니다.

등록·조회·해제는 추가 모델 호출이나 생성 횟수 차감을 하지 않습니다. 이후 명세 생성에는 기존 사용량·비용 정책이 적용됩니다. 이 기능에는 지식 저장소가 필요합니다.

### 검색과 그래프 탐색

DB에 저장된 요구사항·결정·명세를 권한 범위 안에서 검색하고 탐색할 수 있습니다.

검색어를 입력하면 관련 노드와 문서의 해당 부분을 확인할 수 있습니다. 로컬 임베딩을 사용할 수 있을 때는 의미 검색을 활용하고, 사용할 수 없을 때는 텍스트 검색을 사용합니다.

그래프에서는 프로젝트·세션과 노드 종류 등을 기준으로 범위를 좁히고, 노드를 선택해 원본 문서와 연결된 요구사항·결정·명세를 확인합니다. 검색 결과의 일부만 보고 판단하지 않고 원본 문서로 이동할 수 있습니다.

원문·사용자 답변과 모델의 가정은 구분됩니다. 과거 지식이 현재 작업에 참고되더라도 기존 사용자 결정을 자동으로 대체하지 않습니다.

## 사용량과 서비스 이용

작업 화면에서 제공자가 반환한 토큰 사용량과 비용 정보를 확인할 수 있습니다. 제공된 정보가 없으면 사용량을 알 수 없다고 표시합니다. 화면의 비용은 제공자 청구서와 다를 수 있습니다.

공개 서비스에서는 계정별 일일 실행 횟수·비용 한도와 서비스 전체 한도가 적용됩니다. 다른 사용자의 작업이 실행 중이면 새 실행을 시작할 수 없습니다. 질문·승인 대기의 사용권은 3분 뒤 만료되며, 실행 중인 작업에는 이 대기 만료를 적용하지 않습니다.

계정·기록 삭제와 사용 한도 변경은 관리자에게 요청합니다. 운영 방법은 [공개 서비스 운영](PUBLIC_SERVICE.ko.md#관리자와-비용-관리)을 참고하세요.

## 저장과 이어하기

요청·답변·문서 버전·승인과 실행 기록은 PostgreSQL에 저장합니다. 다운로드한 문서 파일은 실행 상태를 대신하지 않습니다.

연결이 끊기거나 서버가 재시작되어도 저장된 자료는 보존됩니다. 실행 중이던 모델 작업은 자동 재실행하지 않습니다. 작업 화면에서 저장된 결과를 확인하고 명시적으로 재개하거나 수정 의견을 보냅니다. 완료 여부가 불명확한 호출은 자동으로 다시 보내지 않습니다.

백업에는 업무 자료의 `core`, 공식 실행 상태의 `workflow`, 계정·비용·사용권 원장의 `public` 스키마가 모두 필요합니다. 운영 절차는 [운영 문서](PUBLIC_SERVICE.ko.md)를 참고하세요.

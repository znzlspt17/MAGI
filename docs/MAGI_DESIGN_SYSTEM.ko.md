# MAGI 공통 디자인 기준

## 제품의 대전제

MAGI는 **문서를 함께 만들고, 근거를 확인하고, 확정하는 차분한 작업대**다. 문서와 판단을 중심에 두고 탐색·대화·검토·승인은 그 작업을 돕는다. 컴포넌트를 추가할 때에도 아래 공간·위계·상태 규칙을 따른다.

## 디자인 토큰과 소유권

| 역할 | 기준 |
| --- | --- |
| 바깥 배경 / 탐색 / 작업판 | `#F8F7FC` / `#F1EEF8` / `#FFFFFF` |
| 주요 행동 / 호버 | `#776095` / `#665080`, 글자 `#FFFFFF` |
| 선택 배경 / 글자 | `#E9E1F5` / `#5F467D` |
| 본문 / 보조 글자 / 경계 | `#2E2936` / `#6D6578` / `#DDD6E8` |
| 바깥 프레임 | 데스크톱 여백·영역 간격 12px, 곡률 18px; 모바일 8px·12px |
| 내부 곡률 | 내용 패널·작성창 12px, 컨트롤 8px |
| 간격 | 4·8·12·16·24·32px |
| 글자 | 화면 제목 24px, 영역 제목 18px, 문서 본문 16px, 조작·설명 14px, 부가 안내 12px |
| 조작 크기 | 기본 최소 높이 36px, 모바일 클릭 영역 최소 44px; 긴 문구는 높이 확장 |

- 색상·서체·공통 컴포넌트 상태는 Astryx Neutral을 확장한 `magiTheme.ts`에서 정의하고 공식 빌드로 생성한다. 생성된 테마 파일을 직접 수정하지 않는다.
- 앱 스타일은 프레임·헤더·페이지 위계·공통 밀도를 소유한다. 공통 UI는 컨트롤과 레이어의 표현·동작을 소유한다. 기능별 스타일은 해당 화면의 배치·읽기 폭·데이터 시각화만 소유한다.
- 같은 요소의 테두리·곡률·높이를 여러 파일에서 중복 정의하지 않는다. 새로운 전역 덮어쓰기를 추가하는 대신 기존 충돌 규칙을 제거한다. 정적 스타일은 명시한 CSS 레이어 안에 둔다.
- 성공·경고·오류의 의미 색상과 Phosphor 아이콘을 유지한다. 긴 설명을 작은 고정 높이 Badge에 넣지 않는다.

## 공간과 정보 위계

- 라벤더 바깥 배경 위에 탐색 영역과 흰색 작업판을 놓는다. 좌우의 위·아래 여백과 네 모서리를 일치시킨다. 헤더와 본문은 오른쪽 작업판 안에 포함한다.
- 모바일에서는 탐색을 Drawer로 분리하고 작업판을 화면 폭에 맞춘다. 헤더·초점 표시를 프레임 모서리에서 잘라내지 않는다.
- 문서·검토처럼 역할이 다른 영역은 패널로 분리한다. 그 안의 요약·도움말은 제목·간격·구분선으로 묶어 장식용 중첩 카드를 만들지 않는다.
- 1920px 이상 문서·검토 간격은 24px, 검토 폭은 `clamp(440px, calc(12.5vw + 200px), 520px)`다. 문서 카드는 남은 폭을 채운다. 문단·목록·인용은 최대 1120px 왼쪽 정렬, 표·코드는 내부 스크롤을 사용한다.
- 1920px 미만 검토 패널의 기존 열기·닫기·Escape·초점 복귀를 보존한다. 문서·대화의 독립 스크롤과 현재 초안을 유지한다.
- 각 작업 영역의 현재 주요 행동을 명시한다. 공유 Button은 기본 secondary, 명시적인 `variant="default"`는 primary다. 파괴적 행동은 destructive, 이동·펼치기·취소 등 보조 행동은 secondary/ghost를 사용한다.

## 공통 패턴

### 탭

화면 전환에는 Astryx 밑줄형 TabList를 사용한다. 둥근 배경을 중첩하지 않는다. 아이콘·글자·선택 표시를 정렬하고 Arrow·Home·End, 비활성 상태, 탭과 패널의 접근성 연결을 유지한다.

### 입력과 작성창

- 검색·설정의 단일 행 입력과 여러 줄 작성창을 명시적으로 구분한다.
- 작성창은 **외곽 테두리 하나 → 입력 영역 → 하단 안내·전송 영역**이다. 내장 TextArea의 중복 테두리·모서리·초점 외곽선을 제거하고 조합 컴포넌트가 입력 초점을 표현한다.
- 하단 전송 버튼은 오른쪽 정렬한다. 좁은 화면에서는 안내가 먼저 접히고 버튼은 남는다. 라벨을 placeholder로 대신하지 않는다.
- 호출부의 rows를 존중하고 자동 높이의 기존 최대 6행·화면 높이 30% 상한을 유지한다. 작은 화면에서는 최소 행 수보다 화면 안 조작 가능성을 우선한다.
- 독립 TextArea·질문 답변·확대 편집에는 필요한 테두리를 유지한다. 확대 편집·초안·한글 조합·최대 길이·Enter와 Ctrl/⌘+Enter·비활성·중복 제출 방지를 보존한다.

### 메뉴와 레이어

- 계정 메뉴는 **정보 → 구분선 → 행동 목록** 순서다. 정보 영역에도 명시적인 패딩을 적용한다. 메뉴 기본 폭 280px, 작은 화면 가장자리 여백 최소 8px을 확보한다.
- 아이콘과 글자·행 높이·호버·초점을 통일한다. 긴 ID와 문구는 줄바꿈한다. 실제 가용 높이가 부족할 때만 스크롤한다.
- UI 어댑터는 크기·스타일 슬롯·아이콘·링크·이벤트·ref·접근성 속성을 전달한다. 미지원 속성을 조용히 삼키거나 이미지·아이콘을 문자열로 평탄화하지 않는다.
- 팝오버·다이얼로그는 12px 곡률과 공통 제목·간격·행동 위계를 사용한다. 중첩 Escape는 최상위 열린 레이어부터 처리하고 호출 위치로 초점을 돌려준다.
- 메뉴의 레이어 간격은 설치된 Astryx의 공식 기본값을 사용한다. SDK가 지원하지 않는 기존 `sideOffset` 속성은 제거한다. 화면 가장자리 8px 확보와 메뉴-호출 버튼 사이 간격을 혼동하지 않는다.

## 적용 및 검증

대표 기준 화면은 새 요청 작성, 문서·검토 작업, 계정 메뉴다. 이후 작업·대화·질문·문서·실행, 프로젝트·지식, 로그인·공개 안내·MCP·관리자에 같은 공통 패턴을 대조한다. API·인증·권한·라우팅·저장 형식은 변경하지 않는다.

- 사용자 제보 5건: 탭 배경/선택 중첩, 승인·의견 영역 배치, 좌우 프레임 불일치, 새 요청 이중 입력 테두리, 계정 메뉴 속성·간격 누락을 회귀 사례로 유지한다.
- 동작 결함은 실패를 재현하고 수정한다. 표현 변경은 기존 동작 검사와 동일 화면·상태의 전후 캡처로 확인한다.
- 390·1440·1919·1920·2560px에서 기본·초점·비활성·로딩·오류·장문을 확인한다. 페이지 넘침 외에 프레임 경계·정렬·간격·텍스트 잘림·강조 위계도 확인한다.
- 실제 브라우저 200% 확대와 동등 viewport/배율 검사를 구분한다. 실행하지 못한 검사는 통과로 기록하지 않는다.
- 모형 API 검사와 실서비스 검사를 구분한다. 전체 테스트·타입·빌드·고지·Astryx 진단과 별도 검토를 마친다. 동작과 시각적 일관성을 모두 충족한 화면만 완료로 표시한다.

### 허용 예외

- 날짜·정밀 숫자 입력 6개는 Astryx Field 안에서 브라우저 제약·정밀 문자열 전달을 유지한다.
- Markdown의 의미 HTML, 차트·그래프 렌더링 및 스크롤·포털 기준 요소는 기능에 필요한 경우 유지한다.
- 긴 단일 행 작업 제목은 원문 접근 수단이 있을 때만 말줄임을 허용한다. 버튼·검토 상태·오류·사용자 작성 내용은 내용을 숨겨 맞추지 않는다.
- 탐색 그룹의 제목은 부가 구분 역할로 12px을 사용한다. 코드·차트 숫자·그래프 글자는 렌더링 역할에 맞는 크기를 유지하며, 모바일 입력은 자동 확대 방지를 위해 필요할 때 16px을 사용한다.

## 기준 변경

새로운 표현이 필요하면 이 문서와 소유 토큰/컴포넌트를 먼저 갱신하고 대표 화면·호출 화면을 함께 확인한다. 화면별 임시 수정이 공통 기준을 대체하지 않게 한다.

## 2026-11-11 적용 및 확인 범위

| 영역 | 적용 내용 | 확인 방식 |
| --- | --- | --- |
| 앱 기반·공통 UI | 테마·프레임·서체·곡률·기본 버튼 위계·탭·작성창·메뉴 | 속성·ref·키보드 회귀, 5개 폭 공통 검사, 대표 전후 시각 검토 |
| 작업·대화·질문 | 요청·초안·질문·평가·의견 입력·현재 주요 행동 | 상태별 캡처, 기존 동작 검사, 승인·수락 영역의 단일 인스턴스 및 중복 제출 검사 |
| 문서·요구사항·실행 | 읽기 폭·검토 요약·다운로드·진행·오류·복구 | 16:9·21:9·좁은 폭 및 장문/상태별 검사, 브라우저 업무 시나리오 |
| 프로젝트·지식 | 상태 표현·영향 분석·입력·필터·설정·그래프 주변 조작 | 소스 대조, 화면 캡처, 필터 Enter/Space·36/44px·한 줄 정렬 검사 |
| 로그인·공개 안내·MCP | 공통 제목·간격·제어 상태·입력·오류 | 정상·빈 상태·오류·로딩 캡처와 기존 테스트 |
| 관리자 | 사용자·작업·사용량·정산·로그의 위계·검색·필터·행동·제목 | 전체 화면 캡처, 검색 단일 테두리·모바일 조회 버튼, 삭제 확인·중복 방지·초점 복귀 검사 |

최종 자동 검사는 프론트엔드 56파일 310개와 고지 2개, 브라우저 업무 시나리오 6개를 포함한다. QA 화면 목록은 25개 화면·상태 × 5개 폭으로 구성하며, 공통 UI 15개 조합 및 초점·접기/펼치기, 문서 레이아웃 23개 상태, 삭제창·경계·Drawer 5개 동작을 별도로 검사한다. 독립 검토는 사용자 제보 5건과 대표 관리자·MCP·지식·작업 화면의 캡처 및 소스를 대조했다. 전체 캡처를 독립 검토자가 모두 수동 검사한 것으로 해석하지 않는다.

실행 결과·상세 캡처는 `.cache/design-system-finish/verification.json`과 같은 폴더, 전체 화면 목록은 `pages/coverage.json`에 기록한다. 재현 절차는 `tests/frontend/qa/README.md`를 따른다.

검사는 모형 API·인증 데이터로 수행했다. 실서비스 계정·OAuth·모델·외부 MCP 및 실기기 모바일 키보드는 실행하지 않았다. 실제 브라우저 200% 확대 조작은 도구가 현재 URL을 확인하지 못해 중단됐으며 동등 viewport/배율 검사만 통과했다. Astryx 설정 검사는 통과했지만, 소스의 CSS·의미 HTML·유지한 Phosphor 아이콘 등에 대한 작성 방식 권고와 빌드의 기존 번들 크기 경고는 남는다. 커밋·운영 배포는 수행하지 않았다.

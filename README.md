# MAGI

**개발 요청을 분석하고 검토해, AI 코딩 에이전트에 전달할 구현 명세를 만드는 도구입니다.**

빠진 정보를 질문으로 확인하고, 요구사항과 결정의 근거를 정리한 뒤 영어 Markdown 명세를 생성합니다. 검토 과정에서 발견한 문제를 보완하고, 사용자가 승인한 문서를 최종 명세로 확정합니다. 대상 프로젝트의 코드 구현과 코딩 에이전트 실행은 별도 단계입니다.

## 주요 기능

- **요구사항 인터뷰:** 한국어 질문과 선택형·직접 입력 폼으로 모호한 조건을 확인합니다.
- **명세 생성과 검토:** 요구사항, 설계, 데이터 흐름, 오류 처리, 인수 조건과 테스트 계획을 정리하고 검토합니다.
- **근거 추적:** 사용자 원문·답변·수정 의견과 모델의 가정을 구분하고, 요구사항과 명세 항목의 출처를 연결합니다.
- **대화와 실행 이력:** 질문·답변·수정·승인 과정을 저장하고 이전 단계의 문서를 확인할 수 있습니다.
- **한국어 보기와 다운로드:** 영어 명세를 기준으로 한국어 번역을 제공하며, 선택한 언어로 다운로드합니다.
- **지식 검색과 그래프:** 저장된 요구사항·결정·명세를 검색하고 관계와 원본 문서를 탐색합니다.
- **사용자와 서비스 관리:** Google 로그인, 사용자별 기록 격리, 관리자 화면, 실행 횟수·예상 비용 관측과 기록 삭제 기능을 제공합니다. 사용량 기준 초과로 실행을 차단하지 않습니다.

## 처리 흐름

```text
명세서 요청 → 계획 → 필요한 작업 실행 → 결과 확인 → 재계획
                ↑                         │
                └── 질문·답변·수정 의견 ──┘
                검토된 후보 → 사용자 승인 → 최종 명세
```

기존 요구사항으로 해결할 수 있는 명세 결함은 보완하고, 새로운 사용자 결정이 필요한 사항은 질문으로 확인합니다. 검토를 통과해도 사용자 승인 전에는 최종 명세로 확정하지 않습니다.

현재 계획과 다음 행동의 이유는 대화에서 확인할 수 있습니다. 질문·승인·문제 해결 대기 중에는 수정 의견을 보낼 수 있으며, 완료된 작업과 명세 버전은 보존됩니다. 서버 재시작 후에는 저장된 상태를 복원하고 사용자가 재개할 때 추가 처리를 시작합니다.

작업마다 OpenAI Conversations API 대화 하나를 유지하며 계획·생성·검토·번역과 후속 수정이 같은 대화를 사용합니다. 대화 ID는 실행 checkpoint와 분리해 DB에 저장합니다. 대화 ID가 없는 기존 작업은 다음 실행에서 현재 확정 요구사항·답변·문서를 초기 자료로 넣어 새 대화를 시작하며, 과거 모델 대화를 복원하지 않습니다.

고정 정책과 초기 자료에 명시적 캐시 경계를 두고 단계별 지시·입력은 뒤에 추가합니다. 작업별 캐시 키와 implicit 캐싱·30분 TTL을 사용하지만, 모델·출력 스키마 변경이나 캐시 만료에 따라 적중 여부가 달라집니다. 대화가 길어지면 입력 비용도 증가할 수 있으므로 관측된 캐시 읽기·쓰기 토큰으로 정산합니다. 초기화 완료 여부가 불확실하거나 연결된 대화에 접근할 수 없으면 자동으로 대화를 교체하지 않습니다.

| 상태 | 의미 |
|---|---|
| `NEEDS_USER_INPUT` | 추가 정보나 결정이 필요합니다. 질문에 답하면 처리를 이어갑니다. |
| `PASS_PENDING_USER_APPROVAL` | 검토를 통과한 후보입니다. 승인하거나 수정 의견을 보낼 수 있습니다. |
| `CRITICAL_BLOCKED` | 추가 결정이나 실행이 필요합니다. 대기 이유를 확인하고 수정 의견 또는 추가 실행을 선택합니다. |
| `FINALIZED` | 사용자 승인을 마친 최종 명세입니다. 다운로드하거나 후속 요청을 이어갈 수 있습니다. |

## 설치와 빠른 시작

### 준비 사항

- Python 3.11 이상과 [uv](https://docs.astral.sh/uv/)
- 화면 빌드용 Node.js 22.12 이상과 pnpm 11.25.0
- OpenAI API 키
- PostgreSQL·pgvector와 Google OAuth 설정

소스에서 실행할 때는 저장소 루트에서 Python 의존성을 설치하고 화면을 빌드합니다. 운영 시 별도 Node 서버는 필요하지 않으며, Flask 게이트웨이가 빌드된 화면을 제공합니다.

```sh
uv sync --locked --group gateway
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
```

### 웹 서비스 실행

[운영 문서](docs/PUBLIC_SERVICE.ko.md)에 따라 빈 DB의 pgvector 확장과 서비스 계정 권한을 준비하고 PostgreSQL·Google 로그인·모델 설정을 실행 환경에 주입합니다. 백엔드는 시작 시 번호별 SQL을 자동 적용합니다. 저장소 루트의 터미널 두 개에서 실행합니다.

```sh
uv run python -m backend.server
uv run python -m flask --app gateway.app:create_app run --host 127.0.0.1 --port 5000 --no-reload
```

운영 환경은 HTTPS 프록시를 사용합니다. 개발 PC의 localhost Google 로그인 설정도 운영 문서에 설명합니다.

### 설정 적용 방식

백엔드와 게이트웨이는 실행 환경에 주입한 설정을 사용합니다. 컨테이너에서는 Compose·Portainer에 설정합니다.

PostgreSQL 연결과 공개 서비스 설정은 필수입니다. 실행 문맥은 공식 PostgreSQL checkpointer, 문서·이력·사용자 결정은 업무 DB에 저장합니다.

## 모델과 언어

생성·검토·컴파일·번역은 **OpenAI `gpt-6-luna`**를 사용합니다. 질문과 검토 설명은 한국어이며, 기준 명세와 정규화된 요구사항은 영어입니다.

명세 화면에서는 한국어와 영어를 선택할 수 있습니다. 한국어 번역은 영어 원문과 별도로 제공되며, 원래 문서의 승인 상태를 바꾸지 않습니다. 번역 시 추가 모델 호출 비용이 발생할 수 있습니다.

## 지식 검색과 저장

PostgreSQL·pgvector에 작업 상태와 단계별 문서, 요구사항·결정·명세의 관계를 저장합니다. 의미 검색에는 로컬 BGE-M3 모델을 사용하며, 유료 임베딩 API로 자동 전환하지 않습니다.

로컬 임베딩을 사용할 경우 의존성과 모델을 준비합니다.

프로젝트의 embedding extra와 gateway 그룹 의존성을 설치한 Python 환경에서 모델 준비 API를 호출하거나, 준비된 모델 폴더를 연결합니다. 별도 모델 준비 CLI는 제공하지 않습니다.

```python
from backend.knowledge.model_files import prepare

prepare("./models/bge-m3")
```

준비한 폴더를 `EMBEDDING_MODEL_PATH`에 지정하고 `EMBEDDING_DEVICE=cpu`를 사용합니다. 서비스 시작 시 모델을 자동 다운로드하지 않습니다. 의미 검색을 사용할 수 없으면 텍스트 검색으로 자료를 조회할 수 있습니다.

작업·문서·이력은 PostgreSQL에 저장합니다. 문서 파일은 다운로드할 때 생성합니다. DB 자동 마이그레이션과 백업 범위는 [운영 문서](docs/PUBLIC_SERVICE.ko.md)를 참고하세요.

| 경로 | 내용 |
|---|---|
| `raw/`, `analysis/` | 사용자 입력, 인터뷰 결과와 확정 요구사항 |
| `review/`, `draft/` | 검토 결과와 승인 후보 |
| `final/FINAL_AGENT_SPEC.md` | 사용자 승인을 마친 최종 명세 |
| `critical/` | 명세 보완 실패 보고서 |
| `completed/`, `history/` | 이전 완료본과 실행 시점의 문서 |
| `translations/` | 원문 버전에 연결된 번역 |

## 사용 범위와 제한

- 명세 생성에는 서버 실행 환경의 OpenAI API 키가 필요합니다.
- 최종 명세는 사용자 승인 후 생성되며, 대상 제품의 코드는 구현하지 않습니다.
- 서버가 중단되면 저장된 기록은 보존되지만 실행 중이던 모델 작업을 자동 재실행하지 않습니다.

## 개발 검증

```sh
uv sync --locked --extra test --group gateway
uv run python -m pytest -q
pnpm --dir frontend test
pnpm --dir frontend build
```

핵심 제품 경계 검사는 `tests/core`에 있습니다. CI는 전용 PostgreSQL·pgvector와 공식 PostgreSQL checkpointer를 사용합니다. 로컬 SQL 대체 검사는 PostgreSQL 운영 복구 검증을 대신하지 않습니다. 브라우저 검사는 빌드한 화면과 가짜 모델 응답을 사용하며, 실제 모델 품질 평가는 별도입니다.
